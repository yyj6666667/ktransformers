KT CPU 舍入位置与数值对齐技术说明
更新日期：2026-10-20

Qwen3.5-35B-A3B 在关闭 LoRA 后，原始 KT 与固定的 Transformers 黄金实现存在前向数值差异。
目前已实现一个 CPU 数值兼容模式：在已测的 8 个样本 × 32 个固定前缀位置上，
全部 40 层 hidden state 误差归零。decode 耗时基本持平，prefill 仍明显变慢。

需要区分两种误差

• 单层误差：每层都使用黄金的输入和路由，单独比较 MoE 输出。
  本次覆盖 40 层，每层 40 个 decode 样本，报告平均 abs mean。
• 整模误差：KT 自己计算路由和 KV cache，误差会沿后续计算传播。
  两边读取相同的固定 token 前缀，比较第 39 层 hidden state 的 abs mean。
  64 个位置和 256 个位置分别代表 8×8、8×32 的测试，不能混作同一口径。

误差如何变化

修改逐步叠加；中间步骤为诊断性算术重放，最终版已落实到实际 KT CPU operator。

状态                         单层 abs mean       整模末层 abs mean（256 个位置）
原始 KT                      8.043×10⁻⁵          0.0131596
移除 down 分片舍入 [R1]      7.614×10⁻⁵          0.0131247
对齐舍入 [R2–R5] 和顺序 [S1] 3.625×10⁻⁷          0.0128956
CPU 数值规则全部对齐          0                   0

最明显的单层变化发生在“按专家 ID 顺序相加”[S1] 这一步：
在此前已对齐各舍入位置的基础上，单层误差由 6.175×10⁻⁵ 降至 3.625×10⁻⁷，
降低约 99.41%，缩小约 170 倍。这是累计修改后的效果，不能算成只改原始 KT 的相加顺序的收益。

但同一步的整模末层误差，在 64 个位置测试中由 0.0109978 升至 0.0116423。
因此，“固定输入的单层更接近黄金”不保证“整模末层误差同步下降”。
残留差异仍会影响后续输入、路由与缓存；这不能仅凭单层均值判断。

为什么会有差异，以及最终如何归零

两边的数学公式相同，但浮点执行过程不同：
• BF16 舍入发生的位置不同，包括分片输出、SiLU、加权和专家累加。
• 专家相加顺序不同；每次相加后都有舍入，所以换顺序会改变结果。
• CPU 与 GPU 的 SiLU 数值、内积累加顺序和截断规则不同。

舍入位置逐项标记

以下以“原始 KT → 最终 CPU 兼容模式”为比较对象。
R 表示数值舍入到 BF16；重新用 FP32 寄存器承载这个值，不会恢复已舍去的低位。
代码位置以 kt-kernel/ 为根目录，行号对应本次交付版本。

[R1 移除｜消融第 1 步] down 分片输出的 FP32 → BF16
  原来：每个 NUMA 内的 down 分片先舍入到 BF16，随后展开为 FP32 加权、合并。
  修改：第一版补丁保留分片 FP32；最终模式按输出列分工，每个输出做完整 K 内积，
        因而不再产生这处“分片输出 BF16 舍入”。
  位置：operators/amx/moe_base.hpp:419 跳过原 to_mat，:85 直接读取 FP32 累加结果；
        最终完整内积见 operators/avx512/sm120_bf16_moe.hpp:180、195、223。

[R2 新增完整输出边界｜消融第 2 步] 完整专家 down 输出 → BF16
  原来：只有分片输出先舍入，没有完整专家输出在加权前的独立 BF16 边界。
  修改：诊断阶段先将分片用 FP32 相加，再舍入完整专家输出；最终模式直接计算
        完整内积后舍入到 BF16，再乘路由权重。它与 [R1] 所处位置不同。
  位置：operators/avx512/sm120_bf16_moe.hpp:196、224。

[R3 新增｜消融第 3 步] SiLU 输出 → BF16，再乘 up
  原来：h = R(SiLU_KT(g) × u)，SiLU 与乘法之间没有独立 BF16 舍入。
  修改：h = R(R(SiLU(g)) × u)，新增的是内层 R；乘完 up 后的外层 R 保留。
        最终模式通过 CPU 查表得到已舍入的 SiLU 值；SiLU 数值实现也另行对齐。
  位置：operators/avx512/sm120_bf16_math.hpp:47（建表时舍入）；
        operators/avx512/sm120_bf16_moe.hpp:175（查表）、176（乘 up 后舍入）。

[R4 新增｜消融第 4 步] 专家输出 × 路由权重 → BF16
  原来：加权与累加融合为 FP32 FMA，没有独立的乘积 BF16 舍入。
  修改：先得到 weighted = R(专家输出 × 路由权重)，再交给累加。
  位置：operators/avx512/sm120_bf16_moe.hpp:205、225。

[R5 从最终一次改为逐次｜消融第 5 步] 每加一个专家后 → BF16
  原来：专家结果在 FP32 中累加，再合并 NUMA 结果，最后输出时舍入一次。
  修改：每一步执行 sum = R(sum + weighted)，下一次相加使用已舍入的 sum。
        最终写出时 sum 已是 BF16 可精确表示的值，不再产生额外数值舍入。
  位置：operators/avx512/sm120_bf16_moe.hpp:206、226；
        208、228 负责写出。

[S1 改顺序｜消融第 6 步] 路由返回顺序 → 逻辑专家 ID 升序
  这一步没有新增舍入位置；它改变 [R5] 每次相加、舍入的先后顺序。
  位置：operators/avx512/sm120_bf16_moe.hpp:152、203、220。

[保留] gate/up 的内积输出仍各舍入到 BF16；乘完 up 后仍舍入到 BF16。
  位置：operators/avx512/sm120_bf16_moe.hpp:172、173、176。
  BF16 舍入函数采用最近偶数舍入；store_bf16 只打包已舍入的值。
  位置：operators/avx512/sm120_bf16_math.hpp:22、31、39。

最终流程中的舍入位置：
  g = R(gate 内积)，u = R(up 内积)〔保留〕
  → SiLU(g) → R〔R3 新增〕 → 乘 u → R〔保留〕
  → 完整 down 内积〔R1 分片舍入已移除〕 → R〔R2〕
  → 乘路由权重 → R〔R4〕
  → 按专家 ID 顺序〔S1〕逐个相加，每次都 R〔R5〕 → 写出。

[内部规则对齐] 上面标记的是算子之间的 BF16 边界；归零还需要匹配内积内部：
  • decode：按黄金的 16/32 路 FP32 FMA 累加链及求和树计算，
    改变中间 FP32 舍入的次序；不是新增 BF16 缓冲区。
  • prefill：匹配每 16 项 MMA 的对齐、截断及向零舍入到 FP32，
    并匹配 split-K 的 FP32 分段相加顺序。
  位置：operators/avx512/sm120_bf16_math.hpp:52、134、182。
  优化路径可用严格区间判断提前确认同一 BF16 结果，不改变上述 BF16 舍入边界。
  这些规则针对本次固定黄金配置；只完成 [R1–R5] 和 [S1] 尚不能归零。

最终版保持黄金不变，在 CPU 上匹配 SiLU、decode 的 FMA 求和树，
以及 prefill 的 MMA 累加、截断和 split-K 顺序。
所有路由专家的 gate/up、SiLU、down、merge 均在 CPU；
attention、router 和 shared expert 仍由原框架在 GPU 上计算。
最终记录中约 1.83 亿个共有 hidden/logit 元素逐位一致。

当前代价和适用范围

相同输入、预热后重复计时的单层 MoE 测试：
• decode 1 token：0.0784 ms → 0.0745 ms，按基本持平理解。
• prefill 128 tokens：3.35 ms → 14.45 ms，耗时约为原来的 4.32 倍。
• prefill 512 tokens：6.01 ms → 54.65 ms，耗时约为原来的 9.10 倍。

因此，当前完成的是固定黄金配置下的前向数值对齐；prefill 的性能代价尚未解决。
兼容模式针对 RTX 5090、cuBLAS 12.8.4.1、torch 2.9.1+cu128 及已验证形状，
并非默认替换全部 KT 内核。此次结果不覆盖 backward、reward 或 RL 训练收敛。
最后的归零步骤包含多项修改，尚缺每项修改对应的完整整模消融数据。
